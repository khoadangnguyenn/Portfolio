# khoadangnguyenn.info.vn

Source of Nguyen Dang Khoa's personal site, https://khoadangnguyenn.info.vn: a resume-style homepage, a publications list, a projects list grouped by area, and blog posts. It is a Jekyll site on GitHub Pages, forked from the Academic Pages template and changed enough that the template's own instructions no longer apply. Pushing to `main` publishes it.

## Run it locally

Ruby 3.3 from Homebrew is the one that works on this machine. From the repo root:

```bash
export PATH=/opt/homebrew/opt/ruby@3.3/bin:$PATH
bundle install
bundle exec jekyll serve --port 4000 --watch
```

Open http://localhost:4000/. Jekyll reloads on content and layout edits, but `_config.yml` is read only at start, so restart the server after changing it. `Gemfile.lock` is in `.gitignore`, so `bundle install` regenerates it.

## Where content lives

The homepage is `_pages/about.md` with `layout: home-resume` (`_layouts/home-resume.html`). The short bio under the name is the body of that file, and the tagline is in its front matter. Name, bio, location, email and social handles are under `author:` in `_config.yml`.

Experience, education, skills and honors on the homepage come from `_data/resume.yml`. An honor with a `proof:` field (a path under `images/honors/`) renders as a link that opens the certificate image in a dialog (`assets/js/story.js`); without JavaScript the link opens the image itself. The same facts are typed a second time in `_pages/cv.md` (the `/cv/` page), and a third time in `files/NguyenDangKhoaCV.pdf`, which the top-menu "CV" link opens. Nothing in the repo generates one from another, so a change to experience, education or honors has to be made in all three. The PDF is the CV of 2026-11-08.

The projects page (`/projects/`, `_pages/projects.md`, rendered by `_includes/area-list.html`) is built from `_data/projects.yml`. The `areas` list defines the groups and their filter buttons; each entry in `items` gives an `area`, `kind` (`repo` or `project`), `start` and `end` months, `summary`, optional `result`, `url` and `thumb`. Inside an area, items sort by `end`, newest first. The `skills` keys on an item must match `key` values in `_data/resume.yml`, which is how the homepage Skills list links to projects.

Publications are files in `_publications/`. The front matter carries `venue`, `authors_short`, `abstract`, `citation` and `skills`; `_publications/2026-07-27-mars.md` is the model to copy. Longer write-ups are in `_portfolio/` (they have pages but are no longer in the top menu, which in `_data/navigation.yml` has Publications, Projects, Blog Posts and CV). Blog posts go in `_posts/`; set `math: true` in a post's front matter to load MathJax.

The previous homepage (`layout: home`, `_layouts/home.html`) is kept as a fallback. It shows a dated news list from `_data/news.yml`; the current homepage does not use that file.

## What is custom

The theme is Academic Pages (a fork of Minimal Mistakes). Everything below was added on top of it, and none of it needs a build step.

- `assets/css/story.css` is the site's own stylesheet, loaded after the theme from `_includes/head/custom.html`. `assets/css/motion.css` holds the animation styles.
- `assets/css/palettes.css` and `_data/palettes.json` are generated by `tools/make_palettes.py`, which also checks text contrast. Edit the palette list in the script, not the CSS. The active palette is `palette:` in `_config.yml`.
- `assets/js/motion.js` draws the local-time clock and the other motion effects; `assets/js/story.js` does scroll reveal, list filters and the certificate dialog.
- Clicking the portrait plays a 3D point cloud of the photo (`assets/js/face-cloud.js`, data in `assets/data/face-cloud.bin`). `tools/face_cloud_bin.py` regenerates the `.bin` from a photo with Depth Anything V2 Small, which needs `torch` and `transformers` and is not part of the Jekyll build.
- `_includes/footer/custom.html` loads MathJax only on pages with `math: true` or `$$`, and Mermaid only on pages that contain a mermaid block.
- The theme's own bundle `assets/js/main.min.js` is built with `npm run build:js` (uglify of jQuery, fitvids, smooth-scroll and `assets/js/_main.js`). Plotly is no longer in it; the old bundle is `_trash_2026-11-26/main.min.js.with-plotly`. Rebuild only if you edit `assets/js/_main.js`.

## How it gets online

Push `main` to `github.com/khoadangnguyenn/Portfolio`. GitHub Pages builds from the root of `main` with the default "pages build and deployment" workflow: the `github-pages` gem, Jekyll 3.10, in `--safe` mode, so plugins outside GitHub's allow-list do not run. There is no custom workflow in the repo.

The custom domain comes from the `CNAME` file. Because the site has its own domain, `baseurl` in `_config.yml` is `""`, and every hard-coded path to an image or file must still be written as `{{ site.baseurl }}/...` so it survives a change of that value.

Before pushing anything that touches `_sass/`, `Gemfile` or `.gitignore`, build a clean clone, because your working copy hides problems that ignored files cover up:

```bash
git clone . ../portfolio-check && cd ../portfolio-check
JEKYLL_ENV=production bundle exec jekyll build --safe
```

## Mistakes already made

On 2026-11-26 the GitHub build failed with "File to import not found or unreadable: vendor/breakpoint/breakpoint". The cause was a `vendor/` line in `.gitignore`, which matches at any depth and so also ignored `_sass/vendor` (breakpoint, susy, font-awesome), which the theme needs. The line is now `/vendor/`, anchored to the root, and the clean-clone build above is what would have caught it.

A `{{` inside a BibTeX block is read by Liquid and breaks the build. Wrap the block in `{% raw %}` and `{% endraw %}`, as `_publications/2026-07-27-mars.md` does.

Changing `baseurl` breaks every image path written without `{{ site.baseurl }}`; search for `src="/` and `url(/` after any such change.

## Rules for content

The ARDEN paper (`_publications/arden.md`) is under anonymous review at AAMAS 2027. The file is in `.gitignore` and has `published: false`, so it is never pushed. For the same reason `robots.txt` blocks `/files/` and `_config.yml` keeps `files` out of the sitemap. Once the decision arrives, at the latest 21 January 2027, remove the `Disallow: /files/` line, the `files` entry under `defaults` in `_config.yml`, and the `published: false` line, and drop it from `.gitignore` if the file should be published.

The MARS manuscript is not on the site. Springer's contract allows the accepted version on a personal page, but only with a note that carries the DOI, and the proceedings are not out yet, so there is no DOI to cite.

Do not put a date of birth or a student ID on the site. The certificate images in `images/honors/` have those blurred and their EXIF data removed; do the same to any new one. Do not write about Hypmotion's internal projects; the work list leaves that work out on purpose.

## The `_trash_*` folders

Directories named `_trash_<date>/` hold files that were taken off the site but may be wanted again. They are in `.gitignore`, so they are neither published nor in git history. Do not delete them.
